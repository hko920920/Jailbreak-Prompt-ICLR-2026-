# h4rm3l–GCG Development Signal-Screen Input Manifest Freeze v1

## Purpose

This stage freezes the exact **hash-only input identities** for the balanced
development signal screen authorized by the successful topology micro-pilot
execution freeze.

It does not run h4rm3l, optimize GCG controls, call the target model, label an
output, open the causal oracle, or create paper-valid evidence.

## Frozen cardinality

The manifest contains:

- 4 development payload identities;
- 3 decoding seeds;
- 12 shared direct instances;
- 24 attacked pair plans: 12 for h4rm3l and 12 for GCG;
- 36 planned baseline generations in total.

The direct result for a payload–seed pair is shared across the two attack
families because the predecessor contract requires the same payload, model, and
decoding.

## h4rm3l assignment

The seven predecessor-audited h4rm3l programs are converted to safe program
identity hashes. The 12 direct instances are hash-sorted and assigned to the
hash-sorted program identities by a balanced cycle. No template, rendered
prompt, component text, or harmful payload is written to a safe artifact.

## GCG assignment

Each GCG plan carries only the pinned source/config identity, the SHA-256 and
lexical-unit count of the initial control, and the frozen optimization budget.
No raw control string is emitted and no optimized control is generated here.

## Evaluator boundary

The logical roles remain frozen:

- WildGuard is a conservative screening signal only;
- HarmBench is a non-voting diagnostic only;
- an automated positive is not a final label;
- two independent blinded annotators and adjudication are required before
  topology analysis.

The predecessor did not freeze exact evaluator model revisions. Therefore this
stage deliberately authorizes only a private runtime-bundle freeze next.
WildGuard and HarmBench-classifier runtime revisions must be pinned before the
first automated label.

## Safe outputs

The workflow records:

- one safe summary JSON;
- 12 direct-instance identity rows;
- 24 attacked pair-plan identity rows.

Raw payloads, templates, controls, prompts, responses, evaluator outputs, and
human-audit packets remain private and unmaterialized.
