# E0 DeepInception Exact-Payload Rerender v2

Date: 2026-08-24 (Asia/Seoul)

## Why v2 exists

The strict official-artifact route failed because the pinned DeepInception data rewrites at least one internal acronym (`IoT` to `iot`). The first exact-rerender adapter preserved that failure and attempted to locate the payload slot using two predeclared antagonist suffixes.

The v1 adapter then passed only 9 of 50 official rows. All 41 failures shared the same error: the text between the payload and the final-layer anchor did not end with one of the two frozen suffixes. No target model was called, and no attack-success result influenced this diagnosis.

This v2 contract removes only the unsupported fixed bridge vocabulary. It does not relax payload identity.

## Frozen length-delimited extraction rule

For every official row:

1. Canonicalize the `plain_attack` by stripping ASCII boundary whitespace and removing at most one terminal period.
2. Find the unique proposal prefix.
3. Define the source embedded payload as the next `len(canonical_goal)` characters.
4. Require that source segment to have the same character length, UTF-8 byte length, and Unicode-casefolded value as the canonical goal.
5. Define every remaining character before the unique final-layer prefix as the bridge or antagonist frame.
6. Require a nonempty bridge of at least four characters.

This rule is source-justified: the ready-to-use DeepInception template places the task immediately after the proposal prefix, followed by framing text and then the final-layer instruction. It does not assume one fixed bridge phrase.

## Derived exact-payload prompt

The derived prompt is constructed as:

```text
source prefix + canonical goal + source bridge + source remainder
```

The adapter must prove that:

- the canonical goal occurs exactly once, contiguously and byte-identically;
- prefix, bridge, and remainder are byte-for-byte unchanged;
- the source's case-modified payload is not used as the experimental goal;
- the prompt is identified as source-conformant derived DeepInception, not an official byte-identical artifact.

## Typed intervention vocabulary

The harmless synthetic prompt is partitioned into seven attack-owned units and one immutable payload fragment:

1. scene and character setup;
2. recursive layer rule;
3. target-depth instruction;
4. per-layer proposal scaffold;
5. bridge or antagonist frame;
6. final practicality requirement;
7. summary instruction.

For each official row, the audit enumerates all 127 nonempty attack-unit subsets and applies:

- deletion of selected unit fragments;
- layout-preserving blanking of selected unit fragments.

This yields 254 static variants per row. Every variant must preserve the harmless sentinel exactly once in both character and UTF-8 byte representations. Blanking must preserve total character and byte lengths; deletion may only reduce them.

## Decision rule

The derived adapter is admitted only when all official rows, all subsets, and both neutralizers pass.

A pass establishes only:

> the pinned DeepInception source supports a source-conformant, exact-payload, seven-unit intervention adapter.

It does not establish attack success, evaluator validity, minimal cut sets, or causal topology.

A failure does not authorize iterative relaxation based on target outputs. The next choice must be either:

- a new source-justified rule frozen before target outputs; or
- replacement of DeepInception by another independent semantic attack family.

## Preserved negative evidence

The following remain true regardless of v2 outcome:

- the official artifact route failed exact payload invariance;
- the v1 two-suffix parser failed on 41 of 50 rows;
- neither failure is reclassified as attack failure;
- target-model outputs, Stage A, held-out data, causal oracle, keep-only oracle, and wavelet remain sealed.
