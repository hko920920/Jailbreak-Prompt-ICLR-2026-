The independent novelty review rejected operator-bound metadata or elementary subset checking
as a novel theorem. Removal specifications are already explicit in
[Covert et al., JMLR](https://www.jmlr.org/papers/v22/20-1316.html), and formal explanation
minimality has substantial prior work. The root and reviewer identified a more concrete
application hypothesis while the V4 outcomes were still uninspected:

Can singleton-based failure tests cause avoidable retention of information in utility-preserving
prompt sanitization, because joint edits restore correctness? The public preprint
[Operationalizing Data Minimization, v1, Section 4.1](https://arxiv.org/html/2510.03662v1)
describes permanently retaining an entity when both its isolated redact and abstract probes
fail. Without an additional utility-monotonicity condition, those two observations alone do
not establish that all joint transformations involving that entity must fail. This is our
logical inference about that documented rule, not an empirical refutation of the paper.

The official repository and current implementation are under read-only review. The accepted
OpenReview PDF currently returns a browser verification page, so the root has not verified
whether the accepted version changes that rule. No claim about accepted-paper mistakes,
privacy performance or a new algorithm is justified at this point. A useful future outcome
would be verified unnecessary retention at equal task correctness, compared with a no-freeze
matched-budget baseline and an exact small-table oracle; mere input-operator disagreement is
insufficient. No such followup experiment has been frozen or launched. V4 remains unchanged.
