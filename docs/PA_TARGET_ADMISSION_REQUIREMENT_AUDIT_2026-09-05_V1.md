# P/A target-admission requirement audit

Date: 2026-09-05 (Asia/Seoul)

Status: ZERO-CALL REQUIREMENT REVIEW / NO TARGET ADMISSION / NO SCIENTIFIC RESULT.

This independent review was requested after the Llama V2 basic admission closed
at 7/10. It reads public protocol/configuration text and the existing safe live
record only. It does not read any private target receipts, historical harmful
payloads or responses, or sealed A60/B60 records. It launches no process, model,
evaluator, download or experiment. Its only written artifact is this document.

## Decision in brief

The original research needs trustworthy fixed-P text interventions, intact full
responses, and evidence that apparent recovery is not loss of ordinary task
capability. It does **not** require a target to answer every factual question
with a punctuation-free ASCII word. The stricter V2 format endpoint is a valid
description of what was tested, but it is not identical to the original
free-response research requirement.

This mismatch does not convert 7/10 into a pass. Llama remains **not admitted**.
The old Step5N fallback cannot be activated after the observed C1N scientific
failure, and Gemma cannot be replaced inside the old C1N result. A separately
declared, outcome-informed DEVELOPMENT route may be designed; it is not an
unobserved continuation of the old confirmation experiment.

The next useful operation is to fix a narrowly task-relevant qualification
contract, not to repeat the same ten trivia questions with a relaxed scorer.
This review recommends a six-call, new-regime DEVELOPMENT smoke below. That
design is a proposal, not a frozen execution contract or permission to generate.

## Which requirements the target actually needs

| Requirement | Necessary meaning for this research | What is merely an implementation choice or insufficient evidence |
| --- | --- | --- |
| Target identity | Pin the exact quantized weights, runtime, template and generation contract so intervention outcomes refer to a well-defined target. Recheck before scientific execution. | This does not establish behavior of canonical BF16 weights, a newer build or a whole model family. |
| Transport and response extraction | Deliver the intended P+A bytes through the declared message/template path; preserve the complete generated answer and reliably distinguish it from prompt echo, logs and protocol data. | The exact old extractor implementation is not a scientific necessity if a new independently verified extraction path has an equivalent explicit contract. |
| Template identity | Establish the actual template transformation and model/template binding prospectively; no arbitrary observed hash may validate itself. | Raw GGUF bytes and an initialized lexer's template bytes need not be byte-identical. V2's independently predicted transformation is the relevant existing evidence, not a license for arbitrary normalization. |
| Input validity and limits | P remains byte-identical exactly once, token/context limits are checked, and malformed or truncated inputs cannot count as recovery. | Short harmless questions do not validate all scientific prompt lengths or intervention layouts. |
| Full response / nontruncation | Retain full responses and classify capped, malformed, interrupted or incomplete results explicitly; these cannot silently count as safety. | Eleven short answers ending normally do not establish that future 512-token responses never truncate. A per-response scientific eligibility check remains mandatory. |
| Ordinary task capability | Demonstrate that the target can perform the selected harmless control tasks, and test capability in separate structure-matched intervention controls when a recovery conclusion would rely on it. | Ten trivia/copy/format fixtures do not establish general intelligence. Punctuation-free ASCII factual words are not a target-wide scientific requirement. |
| Task-required formatting | Preserve exactness where the control task itself measures exact copying or a declared machine-readable interface; distinguish substantive answer errors from format/parse failures. | A JSON or token-copy requirement cannot be generalized to every free-response answer. Conversely, removing all formatting checks would invalidate an exact-copy control. |
| Seed/configuration handling | Fix and audit the exact stochastic scientific settings; evaluate seed robustness using the scientific outcome design. Deterministic control settings can be fixed separately. | One repeated sentinel at seed 17 and temperature 0 does not establish all-prompt determinism, stochastic robustness or behavior at seeds 11/23/47. |
| Measurement coverage | Qualify evaluators separately, freeze their conservative rule, retain ABSTAIN and report coverage/errors/uncertainty and sensitivities. | Harmless target capability cannot admit Llama as a judge, resolve old evaluator disagreements or establish in-domain harmfulness-label validity. |
| Hardware and execution hygiene | Keep the experiment feasible, record settings and relevant resource constraints, ensure owned-process cleanup and exact dispatch accounting. | A particular throughput, GPU-memory delta or temperature threshold is an operational constraint, not the P/A topology estimand. Do not claim an unmeasured thermal or throughput gate passed. |

The distinction between deterministic controls and stochastic scientific
responses matters. D3 deliberately used seed 17, temperature 0 and cap 48 for
arithmetic/copy controls, while scientific recovery required both neutralizers
and seeds 11/23/47. Therefore it would be inaccurate to declare that **every**
capability-control call must use the scientific sampling regime. The actual
scientific request path still needs its own configuration and integrity checks;
the deterministic admission does not automatically cover it.

## What the closed V2 result does and does not establish

The safe record supports these limited existing observations: pinned artifacts
loaded; both owned server lifecycles used the predicted served template; all
eleven bounded requests produced normal stop endings; the sentinel replay
matched; independent reconstruction reproduced the failed result. These are
retained engineering observations, not a new aggregate PASS label.

The three punctuation diagnoses are already outcome-informed. This review has
not re-scored those responses, removed them from the denominator, recomputed a
punctuation-tolerant success rate, or admitted the target using the seven
passing cases. No observation here establishes jailbreak susceptibility,
qualified measurement coverage on Llama responses, recovery topology,
cross-model replication, novelty or ICLR readiness.

## Smallest defensible next qualification design

### 1. Freeze the decision target first; zero calls now

Use a deliberately narrow label such as **DEVELOPMENT SCIENTIFIC-REQUEST-PATH
SMOKE**. It must be separate from V2's failed
basic admission, the old Step5N admission and the failed C1N confirmation.
Record the fact that the new design was motivated by observed formatting
failures. New fixture IDs, new arithmetic operands or a new version number do
not erase that adaptation.

The contract must state the intended future development target, exact generation
regimes, control tasks, response parser, dispatch ceiling, failure handling and
the precise downstream operation it could authorize. It must not authorize
judges, jailbreak inputs, sealed data or paper claims as a side effect.

### 2. Cover the control tasks that already existed before Llama testing

Use the exact P2 arithmetic and token-copy texts already specified by D3, rather
than selecting favorable members of V2's seven passing fixtures. Their
task-selection rationale predates Llama testing. Existing answers to these
instances are exposed, so the new operation is not a fresh test split or an
unobserved capability benchmark. The decision to perform this narrow smoke
after V2's failure is still outcome-informed and must remain disclosed.

There is no need to create new factual questions or change word normalization.
Keep the existing V2 integer and exact-text scorers unchanged for these two
tasks. Exact copy fidelity is the copying task itself; an exact integer answer
is a narrow operational instrument requirement, not evidence that all research
responses must follow that format. Report content/format scorer outcome,
parse status, normal termination and transport integrity separately where the
existing instrument distinguishes them. Do not call rejected extra prose a
factual knowledge error without evidence, and do not silently accept it.

The fact that the same two bare tasks already passed the observed deterministic
regime may be reused as that limited engineering observation. It is not a
replacement aggregate admission PASS and does not substitute for later
structure-matched intervention controls.

### 3. Use a bounded one-shot plan, not repeat-until-pass

If the forthcoming scientific contract retains C1N's generation settings, use
the same two harmless tasks under each of seeds 11/23/47 with temperature 0.7
and cap 512: at most **six** calls. Pin the rest of the scientific decoding
settings and request construction as well; seed, temperature and cap alone are
not the complete configuration.

Do not add two more deterministic control requests and another fresh-process
replay merely to repeat already observed engineering facts under an unchanged
runtime/model/template. An initial broader nine-call candidate would include
those checks, but the narrower six-call matrix addresses the actual untested
configuration without a redundant admission round. Startup identities must
still be checked in any future execution; old success cannot waive a new
identity mismatch.

Six is not six independent scientific cases, a power calculation or a universal
scientific minimum. The exact count covers two already-exposed task inputs and
three planned seed configurations. It does not create content diversity, prove
long-answer capability or establish seed robustness of harmfulness/topology.
A different future scientific sampling plan requires a different prospectively
justified matrix.

For this small engineering smoke, freeze the proposed all-six-correct,
all-six-normal-stop rule before any new call. That threshold is a declared
operational acceptance choice, not a general theoretical capability criterion.
Keep V2's integer/exact-text rules unchanged, make no punctuation relaxation,
and retain every planned result. Use one bounded run, no retries after ambiguous
dispatch, and stop on integrity/transport failures. Preserve a non-passing or
unresolved outcome; do not extend the budget, rotate fixtures or patch the
scorer in order to make the same target pass. Any failure ends this bounded
smoke and is reported before a genuinely new scientific decision. No further
broad capability-benchmark loop is recommended.

### 4. Keep scientific validity checks at their actual point of use

Even a future pass of this small development check cannot replace:

- per-response input validity, cap/truncation and complete-response checks;
- direct-safe/attacked-harmful eligibility under the fixed qualified panel;
- transparent abstention and model/condition/topic coverage accounting;
- structure-matched harmless controls for claimed recovery subsets;
- exact declared subset enumeration, multiple neutralizers and seed robustness;
- separate development and fresh-confirmation evidence boundaries.

The original D3 and C1N failures remain reported. The all-45-already-exposed
payload screen, if later separately frozen and authorized, is DEVELOPMENT
only. It cannot be presented as an unobserved C1N fallback or fresh confirmation.
The original sealed A60/B60 boundary remains closed.
